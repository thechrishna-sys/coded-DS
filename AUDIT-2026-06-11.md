## Scope & Method

Four rounds covering 4 foundation pages + 24 stable components. **In-Progress components were excluded** (Tables, Top Navigation updated, Scroll Bar, Drag & Drop, Illustrative Icons, Graphic Elements, Charts, Date Picker).

| Tool | Status | Used for |
|---|---|---|
| `figma-desktop` MCP (`get_metadata`, `get_variable_defs`) | ✅ Connected | Live Figma variable/effect/text-style extraction per page |
| Browser (Claude in Chrome extension) | ❌ Not available (org restriction) | Would have provided rendered DOM + computed styles |
| Local file system | ✅ | Read `packages/**/*.{tsx,module.css,json}` |

**Limitation:** Audit is source-code-only. Hover/focus/disabled rendered states, computed CSS, and actual visible output were not verified. All claims about state coverage are inferred from CSS `:hover` / `[aria-*]` selectors. `get_variable_defs` returns only variables *used* on the queried node — absence in a response is not proof of deletion.

# Cross-cutting findings

## 1. Foundation drift since last `figma:sync`

Figma's `Warning` and `Information` ramps each added a new shade at the **300** position and shifted the rest. Code is one sync behind. **This silently corrupts any component referencing `--color-warning-300`** (e.g., `Toast` `alert` variant currently picks #FFCD00; after sync the same token becomes #F4DCB2 — a pale tan).

**Fix:** Run `npm run figma:sync && npm run tokens:transform`. Then audit all consumers of `warning-300/400` and `information-300/400`.

## 2. No composite shadow tokens exist (cascades into 10+ components)

Figma defines named composite effects: `Drop Shadow Top/Bottom/Right/Ambient`, `Inner Shadow Top`, `Glass Menus`, `Ascend Analysis`, `Section Depth Effect`, `Panels & Drawers`, `Popovers Shadow`, `Widgets Inner Shadow`. The code exposes only primitive `--shadow-shadow-offset-*` and `--shadow-shadow-blur-*` numbers. Every component that needs elevation has hardcoded the recipe:

- `Popovers Shadow` → Tooltip + Popover + TopNavigation activePill
- `Inner Shadow - Top` → AISearchBar pill + TopNavigation tray + AscendAnalysis (close variant)
- `Drop Shadow - Bottom` → Card (invented variant) + BottomNavigation widget (invented)
- `Panels & Drawers` → not applied to AskAscendPanel (missing entirely)
- `Glass Menus` → not applied to TopNavigation/BottomNavigation

**Fix:** Extend `scripts/transform-tokens.js` to emit composite tokens: `--shadow-popovers`, `--shadow-inner-top`, `--shadow-drop-bottom`, `--shadow-drop-top`, `--shadow-drop-right`, `--shadow-drop-ambient`, `--shadow-glass-menus`, `--shadow-ascend-analysis`, `--shadow-panels-drawers`, `--shadow-widgets-inner`.

## 3. AI-gradient rendered as solid color (5 components affected)

`AIPromptPanel`, `AIButton` (pressed), `AISearchBar` (pill), `AscendAnalysis` all use:

```css
border: 1px solid var(--ai-gradients-stroke-light-ai-gradient-27%, #4dc5b4);
```

The Figma `AI Gradients/stroke-light` is a 2-stop gradient (27% #4dc5b4 → 100% #009a44). Code renders only stop 1 — the AI brand gradient on these components is lost.

**Fix:** Implement a real gradient border (e.g., `border-image: linear-gradient(135deg, #4dc5b4, #009a44) 1`, or the double-background trick). Expose as a CSS utility class `.ds-ai-gradient-border` and reference in all four components.

## 4. Fallback hex mismatches are systemic (~15–25 estimated)

Across components: `var(--surface-fill-cool-neutral-500, #ebeaea)` where the real value is `#EAEEEE`; `--text-tertiary` falling back to `#8a8a8a` instead of `#5E5E5E`; `--icon-hint` falling back to `#b0b0b0` instead of `#8F8F8F`; `--surface-fill-brand-300` falling back to `#d6eef1` instead of `#E2EEEF`; `--surface-fill-cool-neutral-200` falling back to `#f4f6f7` / `#f3f6f6` instead of `#f8fafa`; `--stroke-neutral-300` falling back to `#dfe7e8` instead of `#EBEAEA`.

**Visible failure mode:** in SSR before CSS loads, or if a variable fails to resolve, users see wrong colors.

**Fix:** Add a check script that parses `tokens.css` and every `*.module.css`, flags every `var(--token, #fallback)` where the fallback doesn't match the variable's real hex. Run in CI.

## 5. Material Symbols Rounded is the de-facto icon system

Used by Breadcrumb, Carousel, FilterSort, Menu (via Panel), Panel, Popover, Search, Tag, AscendAnalysis, AskAscendPanel, AIPromptPanel. The DS has `@ds/icons` but isn't used for these.

**Fix:** Either officially adopt Material as the DS icon set (document the font dependency, add load to `apps/docs/app/layout.tsx`), or migrate every Material reference to `@ds/icons`. Pick one.

## 6. Hardcoded pixel sizes despite container tokens existing

~50+ instances of `width: 28px`, `width: 32px`, `width: 40px`, `width: 44px`, `width: 48px`, `width: 56px`, `width: 96px`, `width: 248px`, `width: 312px`, `width: 500px`, etc. as raw values. All have matching `--container-width-*` and `--container-height-*` tokens.

**Fix:** Mechanical refactor — search/replace. Optional ESLint stylelint rule to block raw px values in `.module.css`.

**Fix:** Add motion tokens (`--motion-instant: 80ms`, `--motion-fast: 120ms`, `--motion-medium: 200ms`, `--motion-slow: 320ms`, `--motion-ease-out`, etc.) — a new foundation pillar.
